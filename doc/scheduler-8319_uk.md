# Фонові операції EasyBusyChat 8.3.19 через БСП

Для **BAS Малий бізнес 1.6 / 2.0 з «Контакт-центром» на платформі 1С/BAF 8.3.19** використовуйте `EasyBusyChat_8.3.19_v0.10.4.cfe` **разом із `EasyBusyChatScheduler8319.epf`**. EPF входить до поставки випуску від 02.11.2026 та потрібна для запуску регламентних операцій через БСП 3.1+.

Потрібні [CFE та EPF](../README.md#завантажити-та-обрати-варіант), підсистема БСП «Додаткові звіти й обробки», налаштований API та права адміністратора. EPF викликає серверні процедури розширення; окремої користувацької форми вона не має.

**[Завантажити ZIP-комплект 8.3.19](../releases/2026-11-02/EasyBusyChat_8.3.19_v0.10.4.zip?raw=1)** — CFE, EPF, українська інструкція та налаштування БСП в одному архіві. Розпакуйте ZIP перед підключенням файлів.

## Підключення

1. Установіть CFE, перезапустіть клієнт і виконайте початкове налаштування EBC.
2. В адміністративних налаштуваннях BAS увімкніть додаткові звіти й обробки. У їх списку додайте [EasyBusyChatScheduler8319.epf](../releases/2026-11-02/EasyBusyChatScheduler8319.epf?raw=1) з файлу. Назви розділів залежать від редакції BAS та БСП.
3. Переконайтеся, що з’явилася обробка **«EasyBusyChat: фонові операції (8.3.19)»**, версія **1.0**, та три команди нижче. Версія EPF окрема від версії CFE 0.10.4.
4. Перегляньте дозвіл безпечного режиму: HTTPS до `api.easy-busy.cloud:443`. Для іншої адреси API потрібне погоджене доопрацювання дозволу в EPF. Не вимикайте безпечний режим EPF як універсальний спосіб обходу помилки.
5. Для **кожної команди окремо** налаштуйте виконання за розкладом, увімкніть використання та збережіть картку. Додавання EPF саме по собі не вмикає розклади.

| Команда | Ідентифікатор БСП | Призначення |
|---|---|---|
| Ротація логів | `EBC_РотацияЛогов` | Очищення журналу за налаштованим строком зберігання |
| Синхронізація довідників | `EBC_СинхронизацияСправочников` | Компанії, облікові записи, користувачі |
| Синхронізація чатів | `EBC_СинхронизацияЧатов` | Оновлення чатів та останніх повідомлень |

## Рекомендований початковий розклад

| Операція | Розклад | Налаштування періоду |
|---|---|---|
| Синхронізація чатів | **Щохвилини** | Щодня протягом доби, повторення через 60 секунд |
| Синхронізація довідників | **Кожні 15 хвилин** | Щодня протягом доби, повторення через 900 секунд |
| Ротація логів | **Щодня о 03:00** | Один запуск на добу, без повторення протягом дня |

Час 03:00 задається за часом інформаційної бази / сервера виконання. Якщо в цей час заплановано резервне копіювання або обслуговування, перенесіть ротацію на вільний час. У файловій базі оберіть час, коли працює сеанс, що обслуговує фонові завдання.

Це початкові рекомендації, а не розклади, які EPF вмикає автоматично. Хвилинний інтервал підтримує актуальність чатів; довідники зазвичай потребують рідшого оновлення, а журнал достатньо очищати раз на добу. Після першого дня роботи перегляньте тривалість запусків та помилки API. Якщо синхронізація чатів триває понад хвилину або з’являються відповіді 429, збільште інтервал до 2–5 хвилин; за потреби довідники оновлюйте кожні 30–60 хвилин. Не запускайте ту саму операцію паралельно й не дублюйте її іншим механізмом розкладу.

## Перевірка

Виконайте вручну спочатку синхронізацію довідників, потім чатів. Ротацію запускайте після перевірки строку зберігання. Перегляньте історію виконання БСП, журнал реєстрації та журнал EBC. Дочекайтеся хоча б одного запуску кожної команди за розкладом і звірте час наступного виконання.

У файловій базі перевірте, який сеанс обслуговує фонові завдання: EPF не забезпечує роботу при всіх закритих клієнтах. На сервері перевірте, що регламентні завдання не заблоковано. Поведінка залежить від платформи й конкретної БСП.

| Симптом | Що перевірити |
|---|---|
| Немає трьох команд | Файл EPF та сумісність БСП |
| Метод або модуль EBC не знайдено | Чи активне потрібне CFE, чи перезапущено клієнт |
| Помилка доступу до API | Дозвіл EPF на адресу API, HTTPS і токен |
| Розклад є, запусків немає | Використання команди, блокування завдань, сеанс файлової бази |
| Завдання успішне, але оновилася частина даних | Попередження журналу EBC: часткова синхронізація може завершуватися без загальної помилки |

Відповідність трьох команд серверним викликам перевірена за кодом; роботу в конкретній БСП ще потрібно перевірити.
